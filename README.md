# 天行 · AI-CEO 经营早报（任务闭环看板）

把每周任务清单（Word / Excel（含老版 .xls）/ CSV / 纯文本）上传后，**自动解析 → 汇总分析 → 跨周整合**，生成一份 AI-CEO 风格的「经营早报」看板。

零第三方依赖，标准库即可运行；首次启动自动建库。

> **本分发版说明**：不含任何大模型密钥，也不含真实经营数据。首次运行会自动创建一个空数据库，你上传自己的周报后即可使用。若想启用「AI 智能抽取」，在页面右上角「大模型」里填自己的密钥即可（仅存于本地，不会外传）。

## 一、怎么跑

```bash
# 1) 启动服务（默认 8000 端口，可指定端口）
python app.py
python app.py 9000

# 2) 浏览器打开
http://127.0.0.1:8000
```

打开后：拖拽 / 点击上传本周任务清单（`.docx / .xlsx / .xls / .csv / .txt`），系统自动解析并刷新早报。
上传多份 = 多个周次，点「跨周整合」看趋势、未闭环滚存、跨周承压人员（可先勾选参与对比的周次，默认全选）。

**上传后立刻能看到识别结果。** 每份文件在上传区下方展开一张「本次识别到的任务清单」：逐条列出 序号 / 状态徽标 / 任务标题 / 责任人，标注本次识别方式（标准任务表 / 5W2H 派单块 / 状态汇总表 / 纯文本兜底 / AI 抽取）与承接人数，并带「在下方看板中查看」按钮直接跳到该周次早报。识别不到结构时，该处直接给出原因与下一步建议，不会静默失败、也不会产生空周次。每张清单右上角带「收起 / 展开」按钮，一次上传多个文件时可逐个折叠、互不影响；重新展开时列表自动回到顶部。

若某个文件没解析出任务，上传区会直接给出原因提示（详见第二节），不会产生空周次。

**历史周次可管理、报告可下载：**

- 顶部「下载早报 / 下载跨周报告」按钮：把生成的汇总分析报告保存为本地 HTML 文件（浏览器自动下载，可打印 / 微信传阅 / 归档）。
- 「历史周次」表每行有 **查看 / 报告 / 删除** 三个操作：「报告」下载该周单份 HTML；「删除」移除该周次及其全部任务，不可恢复。
  删除采用**页内二次确认**：第一次点「删除」按钮变为红色「确认删除」，4 秒内再点一次才真正执行，超时自动还原。这样不依赖浏览器原生弹窗（内嵌预览面板、部分 webview 会拦截 `confirm` / `alert`，导致点了没反应）。
- 顶部「刷新早报 / 跨周整合」按钮带**明确反馈**：点击后按钮立即变为「刷新中… / 整合中…」（至少可见 0.4 秒），顶栏徽标刷新为「更新于 `HH:MM:SS` · 当前周次」并闪一下，同时弹出底部轻提示；点「刷新早报」会自动收起跨周整合区并回到页面顶部。本地接口毫秒级返回，数据未变时页面内容本就一致，缺少这些反馈极易被误判为按钮失效。
- 服务端对所有页面与接口响应下发 `Cache-Control: no-store`。内嵌预览面板与部分 webview 会对没有缓存头的 HTML 做启发式缓存，从而一直显示旧版页面，这是前端改动看不到效果的常见原因。

> Windows 一键启动见 `run.bat`（双击即可）。

### 只想立刻看效果（不启动服务）

直接用浏览器打开 `早报示例_2026-10-12.html` —— 这是基于真实周报自动生成的离线快照，双击即开，可微信 / 安卓传阅。

## 二、支持的上传格式与识别结构

**三类任务结构 + 一层兜底，按优先级自动匹配：**

| 优先级 | 结构 | 长什么样 | 抽取内容 |
| --- | --- | --- | --- |
| 1 | **标准任务表** | 表头含「任务 / 责任人 / 完成状态」三列（时限、依据、备注可选） | 逐行任务 + 责任人 + 状态 + 时限 |
| 2 | **5W2H 派单块** | `任务 1：标题`，下面跟 `• Who（谁）：…` `• When（何时）：…` `• How much（验收标准）：…` | 任务标题 + 责任人（去角色后缀）/ 时限 / 验收标准 |
| 3 | **状态 × 涉及任务 汇总表** | 表头「状态 / 项数 / 占比 / 涉及任务」，任务名用「、」拼在一格 | 自动按顿号拆成逐条任务（括号内人名提为责任人），状态取所在行 |
| 兜底 | 自由文本 | 纯文本派单行 | 只收含责任人的行；无责任人 / 报告式条目（项目符号、5W 建议、小标题）直接丢弃 |

| 文件格式 | 抽取方式 |
| --- | --- |
| `.docx` | OOXML 直接解包：段落 + 全部表格，再按上表匹配 |
| `.xlsx` `.xlsm` | OOXML 工作表（含 sharedStrings 还原） |
| `.xls` | 老版 Excel 97-2003（OLE2 复合文档 + BIFF8 记录流），**零依赖原生读取**，无需另存为 .xlsx |
| `.csv` `.tsv` | 逗号 / 制表符分隔，整份文件视为一张表（首行表头） |
| `.txt` | 先按 `|` / `\t` 识别表格块，否则走自由文本兜底 |

> **判型靠文件内容，不靠扩展名。** 上传时先读文件头魔数（OLE2 `D0CF11E0` / ZIP `PK` / 纯文本），再决定解析通道。真实业务里常见「把 `.xls` 直接改名成 `.xlsx`」（Windows 只改后缀、内部仍是 BIFF8 二进制），若只信扩展名会被送去 OOXML 解析而必然失败。遇到扩展名与真实格式不一致时，系统按真实格式解析，并在上传提示里明确告知（如「该文件扩展名为 .xlsx，但内部实为 Excel 97-2003（.xls）二进制格式，已按 .xls 正常解析」）。

> **老版 `.xls`（Excel 97-2003）兼容**：无需在 Excel 里另存为 `.xlsx`。系统用内置的零依赖读取器（OLE2 复合文档解析 + BIFF8 记录流解析，覆盖 BOUNDSHEET/SST/LABELSST/LABEL/NUMBER/RK/FORMULA 等记录）直接读取，与 `.xlsx` 同源、同一套结构识别逻辑。该读取器与 openpyxl 做过逐格比对（208 格 100% 一致）。若 `.xls` 读取失败（加密 / 损坏 / 非标准格式），会明确提示「请在 Excel 中另存为 .xlsx 后重试」，不会静默乱码。

> **派单计划表（无完成状态列）**：真实业务里很多周计划表只有「任务 / 责任人 / 时限 / 依据 / 验收标准」，没有「完成状态」列。系统不再强行要求状态列，这类表会全部按「进行中」登记，并在上传提示里明确说明「本表未含完成状态列（属派单计划表），拿到完成反馈后再上传一次即可体现闭环」，不会产生空周次，也不会误判为已完成。

**状态自动归一化**：已完成/收齐/归档 → 已闭环；部分/召开/讨论/收尾 → 收尾中；进行中 → 推进中；未反馈/仅收到/未见/零回应 → 卡住未反馈。

**识别不到任何结构时会拒收，而不是硬凑：**

- 结果是 **0 项 + 明确原因，不写入库**（避免空周次污染历史与跨周趋势）。
- 提示里会说明支持哪三类结构，并建议勾选「使用 AI 智能抽取」由大模型按反幻觉规则抽取行动项。
- 勾选了「AI 智能抽取」但**大模型尚未配置**时，会明确提示「大模型尚未配置，本次按规则解析」，不会假装已经用了 AI。

**责任分布表**（表头「责任人 / 承接任务数 / 已完成 / …」）会被一并读出并随周次持久化，用于「人的信号」面板；其中「部分 / 未反馈」这类合并列会按斜杠拆成两个口径，不再重复计数。

> 实测：`天行公司交流群周报_20261012.docx` → 标准任务表，18 项；`天行公司_上周工作综合分析与非标任务安排_20261012.docx` → 5W2H 派单块，9 项派单（责任人全部到位）+ 12 人责任分布表；`2026.10.12-2026.10.18（第41周）工作计划安排.xls`（老版 Excel 97-2003、5W2H 派单表、无完成状态列）→ 13 项派单、9 名责任人，自动按「进行中」登记并提示缺状态列。
>
> 同源文件若被改名为 `.xlsx`（Windows 只改后缀、内部仍是 BIFF8 二进制）同样可直接上传：系统按魔数判为 `.xls` 并正常解析出 13 项任务，同时在上传提示中说明「扩展名为 .xlsx、内部实为 .xls」。反向（真 `.xlsx` 改名为 `.xls`）亦然。
>
> 三份文档都可直接上传，无需改名或改格式。

## 三、看板模块（对应前期 AI-CEO 方案）

界面自上而下分四层，同一批数据的四种聚合口径：

1. **一句话结论**：本期派单 / 闭环 / 四态计数 + 主要风险，滚动式陈述。
2. **核心 KPI（5 项）**：经营健康指数（规则合成分 0~10）、行动闭环率（加权）、风险项、逾期行动、派单总数。
3. **四态分布条**：一条彩条按四态占比铺开，下方图例带计数 —— 四态计数只在这一处出现，不再与 KPI 重复。
4. **主体双栏**：
   - 左栏 **异常警报（今天什么会炸）**：零回执任务、成果无载体、单点依赖 / 承接过度集中、派单回收错配、逾期，每条带处置建议与风险等级标签。
   - 左栏 **人的信号（谁好谁差）**：按风险优先排序（卡单多者在前），默认展示前 8 人，其余点「展开其余 N 人」；每人一条四态堆叠条，自动标注零回应 / 单点依赖。
   - 右栏 **任务闭环看板**：四态泳道（已闭环 / 收尾中 / 进行中 / 卡住未反馈），每张卡带责任人与来源依据。
5. **跨周整合**（按钮触发）：顶部先选参与周次，再出结果。
   - **参与周次**：库内每个周次一个圆形勾选徽标（显示周次代号与任务数，悬停看完整标签），默认首次打开全选；右上角四个快捷键「最近 4 周 / 最近 2 周 / 全选 / 清空」。勾选变化后自动重算，无需再次点按钮。
   - 选定下方即闭环率趋势、未闭环滚存、跨周持续承压人员，三者都只基于所选周次计算。滚存与人员一致性需要 2 个及以上周次，只选 1 个时页面会给出说明。
   - 顶部「下载跨周报告」导出与页面所选范围完全一致的 HTML，报告抬头会写明覆盖了哪几个周次。
   - 接口：`GET /api/consolidated?weeks=18,19`，省略 `weeks` 表示全部周次；`GET /api/report/consolidated?weeks=18,19` 同理。

响应式：≤1180px 主体转单栏、KPI 转 3 列；≤720px（手机）KPI 转 2 列、泳道单列、顶栏不再吸顶。

## 五、可选：接入国内通用大模型（可插拔）

**是否需要接入大模型？** 取决于你上传的是什么源：

- **结构化任务表单**（docx/xlsx/xls/csv 表格，含任务/责任人/状态列）：规则驱动已够用，**不需要**大模型，离线可跑、结论可溯源。
- **纯文本 / 群消息 / 会议纪要**：要让系统从非结构化文本自动抽取行动项，**必须接入大模型**，否则只能靠粗糙的关键词兜底。
- 大模型还负责把规则生成的「一句话结论」润色成自然语言综述 + 今日督办焦点。

**怎么配置（页面内即可，无需改代码）：**

1. 打开页面 → 展开「大模型配置」面板。
2. 选服务商（DeepSeek / 通义千问 / 智谱 GLM / 豆包 / Kimi），或选「自定义」填 Base URL 与模型名（适用于 Agnes 等任意 OpenAI 兼容端点）。
3. 填 API Key → 点「连接测试」→ 点「保存配置」。
4. 当文件不是上述三类结构（纯文本纪要、群消息记录等）时，勾选「使用 AI 智能抽取」；想让结论叙述更自然则勾选「用于结论增强」。规则能识别的文件不需要 AI。

配置会落在 `config.json`（明文存本地）；也可用环境变量 `CEO_LLM_BASE / CEO_LLM_KEY / CEO_LLM_MODEL` 兜底（不落盘）。

**国内通用端点速查（均为 OpenAI 兼容 `/chat/completions`）：**

| 服务商 | Base URL | 默认模型 |
| --- | --- | --- |
| DeepSeek（深度求索） | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 通义千问（阿里） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 智谱 GLM（清华） | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| 豆包（字节火山引擎） | `https://ark.cn-beijing.volces.com/api/v3` | `doubao-seed-1.6-250615` |
| Kimi（月之暗面） | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 自定义（如 Agnes） | 你提供的 `/v1` 或 `/v3` 等前缀 | 按服务商文档填 |

> 关于 Agnes：若它提供 OpenAI 兼容的 `/chat/completions` 接口，选「自定义」填 Base URL + 模型名即可；若协议不兼容，需提供其接口文档再对接。

**安全红线（已写进每个提示词，模型无法绕过）：**

1. 责任人只能命中「花名册」已有姓名，无法归属填「未指派」，严禁编造新姓名。
2. 每条判定（状态/时限/依据）必须有原文证据，`evidence` 字段逐字引用，不凭印象补全。
3. 原文未出现的状态/时限/结论/数字一律不输出；宁可少抽，不可臆造。
4. 任何 LLM 调用失败都静默回退到规则版，不阻断主流程。

**隐私提示：** 任务清单含公司内部信息，建议用私有部署或仅在可信网络配置；密钥以明文存于本地 `config.json`，生产应改用环境变量或密钥管理。

## 六、外接企业微信（自建应用 · 群消息自动入板）

把 AI-CEO 注册成企微「自建应用」的**消息接收后端**：企微服务器会主动把群里 @应用的消息推送到 AI-CEO，自动抽取任务并生成看板。这是 7×24 自动运行、不依赖任何人工或本会话的可靠方案。同时提供通用的「结构化任务推送」入口，任何系统（脚本 / 第三方）都能把任务 POST 进来。

### 6.1 在企微管理后台配置（一次性）

1. 进入「企业微信管理后台 → 我的企业」记下 **CorpID**；「应用管理 → 自建 → 创建应用」记下 **AgentID** 与 **Secret**。
2. 在该应用的「接收消息」里点「设置 API 接收」，填入：
   - **URL**：`https://<你的部署域名>/wecom/callback`（本地调试用 `http://127.0.0.1:8000/wecom/callback`；但企微要求公网 HTTPS，正式用线上部署地址）。
   - **Token**：任取一串字符串，记下来。
   - **EncodingAESKey**：点「随机生成」即可。
3. 点「保存」时，企微会向该 URL 发一次 GET 验证；AI-CEO 自动解密回显 `echostr` 完成校验（无需你手动处理）。

### 6.2 在本系统填入凭证

**操作顺序：先配本应用，再去企微后台点「保存」。** 顺序反了会报「openapi回调地址请求不通过」——因为企微点保存时会立刻向回调地址发验证请求，此时应用还是空配置，只能回 403。

1. 打开 AI-CEO 页面 → 展开「企业微信接入」面板 → 填入 **Token / EncodingAESKey / CorpID**（AgentID 仅记录，不影响验证）→ 勾选「启用回调接收」「自动入库群任务」。
2. 点 **「配置自检」**：本地跑一遍完整加解密回环（Token 非空 / AESKey 43 位且可解码 / 签名校验 / 加解密一致 / receiveid 回带），不过则逐项告诉你哪里错，不必等企微来撞。「保存配置」时也会自动先自检，不通过不让存。
3. 自检通过后点 **「保存配置」**，然后才去企微后台填回调地址点「保存」。

配置以明文存于部署端 `config.json` 的 `wecom` 段（与「大模型配置」同文件）。

> 回调地址已在面板里自动显示并带「复制」按钮，直接粘到企微后台即可，避免手抄出错。

### 6.3 智能机器人长连接（BotID / Secret，无需公网 IP）

若没有公网 HTTPS、或不想配 Token/AESKey 与加解密，可用企微「智能机器人」的长连接方式接入：

- 企微管理后台创建「智能机器人」，开启「API 模式 → 长连接」，得到 **BotID** 与 **Secret**（长连接专用，与自建应用 Token/AESKey 不同；两种模式互斥，切到长连接后原回调地址即失效）。
- AI-CEO 页面 →「企业微信接入」→ 切「智能机器人长连接」标签 → 填 **BotID / Secret** →「保存配置」（可选「保存后自动连接」）。
-「测试连接」会用 BotID/Secret 换一次 access_token 校验凭证；「连接」在本服务内起一条常驻 WebSocket 长连接到 `wss://openws.work.weixin.qq.com`，自动订阅并接收群内 @机器人 / 私聊文本消息。
- 收到消息后，AI-CEO 用与自建应用相同的规则（或大模型）抽取任务入库生成看板；勾「收到后自动回复」时通过 `aibot/send_msg` 回「已收录 N 项任务」。

原理：长连接由本服务主动连企微（无需公网入口），消息不经 AES 加解密，部署成本最低；代价是本服务进程需常驻并维持心跳（约 30s），同一机器人同时仅一条长连接，断线指数退避自动重连。凭证同样明文存于 `config.json` 的 `wecom` 段。

### 6.4 在群里怎么用

群里 **@ 该应用** 发任务即可，例如：

```
@AI-CEO 【任务】整理合同台账 负责人：张三 截止：本周五
@AI-CEO 【督办】回访客户A 责任人：李四 状态：进行中
```

AI-CEO 收到后：解密 → 抽取任务（开启了大模型则走 LLM 高质量抽取，否则规则兜底）→ 入库生成「企微群·当天日期」周次 → 若勾选了「收到后自动回复」，会在群里回一句「已收录 N 项任务」。同一消息企微可能重试投递，系统按 `MsgId` 去重，不会重复入库。

### 6.5 通用结构化推送（不依赖企微也能用）

任何系统都可以直接 POST 任务到 `POST /api/tasks`（JSON）：

```json
{ "label": "外部推送 2026-10-19",
  "source": "api",
  "tasks": [
    {"title": "整理合同台账", "owners": ["张三"], "status": "doing", "due": "本周五", "note": "来自XX系统"},
    {"title": "回访客户A", "owners": ["李四"], "status": "stuck"}
  ] }
```

`status` 取 `done / partial / doing / stuck` 之一（缺省 `doing`），`owners` 为空时记「未指派」。返回新生成的周次与早报。这是把 ERP / 工单 / 邮件等任何来源接入看板的最快路径。

### 6.6 反向：早报主动推送到群

在「企业微信接入」面板填 **群机器人 Webhook**（企微群 → 群机器人 → 添加机器人 → 复制 Webhook 地址），点「推送早报到群」，AI-CEO 会把最新早报的核心 KPI 与结论推到群里，形成「群里下任务 → 系统跟踪 → 群里播报」的闭环。

### 6.7 安全与限制

- 企微回调要求**公网 HTTPS** 且 5 秒内响应；本系统部署在 WorkBuddy Sites 上即满足。回调体强制 AES-256-CBC 加密，消息解密用内置的**纯 Python 实现**（零第三方依赖，已用 NIST 测试向量逐字节验证）。
- Token / EncodingAESKey / CorpID 属企业凭证，**明文存于部署端 config.json**；仅在自有且可信的部署环境开启回调。
- 企微群机器人（Webhook）只能**发**消息、不能收；要自动收群任务必须用「自建应用 + 回调」这一条路（见 6.1）。

### 6.8 排障：企微后台报「openapi回调地址请求不通过」

按出现频率从高到低：

1. **本应用还没配 Token / EncodingAESKey / CorpID**（空配置时任何验证请求都被应用拒绝，回 403）。→ 按 6.2 先填本应用并「保存配置」，再去企微后台点保存。
2. **两边凭证不一致**：Token 或 EncodingAESKey 在企微后台和本应用填得不一样（含大小写、空格）。→ 重新整串复制，两边保持一致；可用「配置自检」先验证本应用侧格式。
3. **EncodingAESKey 不是 43 位**：企微后台可点「随机生成」；粘贴时注意别带入换行或空格。
4. **回调地址写错**：必须是 `https://<域名>/wecom/callback`（无多余路径、无查询参数）。
5. **实例冷启动超时**：长时间无人访问后首次请求可能超过企微的 5 秒时限。→ 先打开一次应用首页「预热」，再点企微后台的保存。
6. **用了明文模式**：面板请选「安全模式」；本系统的解密逻辑按安全模式实现。
